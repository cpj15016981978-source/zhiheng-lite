—— 运行与验证说明
========================================================================

平台与依赖（先看这段）
--------
- 本地 OpenAI 兼容口：`POST /v1/chat/completions`、`GET /v1/models`、`GET /v1/status`，仅回环；标准客户端可直接接 `http://127.0.0.1:8753`。
- 推荐启动：双击 `start.bat`（ASCII 文件名，zipball 下载不会乱码）；接真实模型用 `start-live.bat`，双模型用 `start-dual.bat`。
- 启动门禁 `preflight` 失败时改为警告并继续降级启动，不再直接卡住双击入口。
- 仅支持 Windows。代码使用 DPAPI、WINFUNCTYPE、PowerShell、注册表等 Windows 能力。
- 没有跨平台承诺；macOS/Linux 需要另开移植，不是当前分支的目标。
- 不是“零第三方依赖”。实际运行时依赖见 requirements.txt：
  pypdf、python-docx、openpyxl、zhconv、vosk、apscheduler、qwen-agent、soundfile 等。
- 本地模型、DeepSeek/OpenAI 兼容 API、Qwen-Agent 都是可选路径；具体以设置页为准。
- agentd 默认不启动：审批走 ledger；需要 token 档时再单独启动 agentd。
- 许可证：Apache License 2.0，见 LICENSE、NOTICE、THIRD_PARTY.md。
- 安全边界与报告方式：见 SECURITY.md。
- 首次启动自动创建 %LOCALAPPDATA%\Zhiheng\data；程序目录不写用户数据。

这是什么
--------
一条端到端、且会【主动找你】的通路：
    你输入 → 编排(M1) → 反思(M4:蒸馏事实+提炼原则) → 记忆召回(M2)
           → 带着“自写原则”构造上下文 → 模型(M10，mock 或已配的真模型) → 回应 → 落库
           → （开了 :voice 才有的最后一步）M14 用本机嗓子把回应念出来
    另一条：外部时钟定期 M1.tick(now) → M6挑到期触发器 → proactive组织主动消息 → outbox
Phase1 证明【关掉也不消失】+【会记住】；
Phase2 再证【越用越懂你】（蒸馏事实、自写处世原则）；
Phase3 再证【不打开软件它也会主动找你】，且“主动必须有正当理由”(防骚扰)。
Phase5.5 再证【记了能取出来 + 有界面可用】；
Phase5.6 再证【它会看脸色（但只当估计）+ 两轮之间是同一个我（身份可审计、改口留痕）】。

技术栈（ADR-005）
----------------
Python 3.13 + sqlite3 + 若干第三方解析/语音库；Windows 本机安装。依赖清单以 requirements.txt 为准，不再声称零第三方依赖。

怎么跑（两种形态，共用同一个记忆库）
------
① 本机界面（Phase5.5，双击即开）

    双击  打开界面.bat        → 自动起服务并自动打开浏览器 http://127.0.0.1:8753/
    或：   python webapp.py    （--port 换端口 | --no-browser 只起服务 | --live 先盲输密钥）

    左边对话，右边是它的内心：事实 / 原则 / 我和心境 / 主动 / 对话 五栏，随时能"忘掉这条"
    "作废这条"（作废会问你理由，理由连同旧文本一起进库留痕，改过的口都查得到）；
    下面两个按钮手动反思、手动拨时钟看它主动找你。
    每条回应下面那行灰字是【铁律6】：把"查到的"和"我推断的"分开写，不拿猜测当事实；
    还会写上当下的【心境估计】与【身份版本】——心境只是估计，不是诊断，也不说给你听。

    三条底线（不可放宽）：只绑 127.0.0.1（Host 不是本机直接 403）、页面只用 textContent
    渲染（记忆里的 <img onerror> 不会被执行）、不接收也不落盘任何密钥（贴进来照样被拦）。
    目前只能在命令行 :remind 设提醒，界面里先只负责"看它推来的话"。

② 命令行

    python chat.py

然后在“你 >”后面直接打字对话。命令：
    :facts        看它记住了哪些事实
    :principles   看它自己写下的处世原则（Phase2）
    :reflect      手动触发一次反思（平时对话已自动反思）
    :remind       登记一条主动提醒（会让你填“正当理由”）——Phase3/3.5
                  类型: manual | once|时间 | daily | annual|月-日 时:分 |
                        weekly|星期 时:分 | silence_days|天数 | fact_exists|主语/谓语
    :tick         模拟时钟滴答，触发到期的主动推送——Phase3
    :inbox        看它主动推给你的话（收件箱）——Phase3
    :council      开/关两模型互审（:council mock,mock 开；:council off 关）——Phase4
    :review       开/关【自我批判】（:review on 开；:review off 关；:review status 看上一轮）
                  ——SC-1 二版，ADR-039。关掉=回答一个字都不改（发现的问题只记录，
                  不调模型、不多花钱）；逐字相同这一点由 3 条 golden 回归测试钉住
    --- 记忆体（Phase5：能改口、能忘掉、能作废、能备份）---
    :history      看它【改过口】的旧事实（可加参数：:history 用户 职业）
    :forget 编号  忘掉某条事实（编号见 :facts）
    :purge 关键词 把命中的【原文全库】忘掉（X3 三版，ADR-034）：对话/事实/主动消息/提醒删行，
                  情绪线索复位，命中原则置占位并停用，改口流水只清文本、行保留（删流水=造假账）
                  —— 误贴密钥等敏感内容用它，不必手改数据库
    :retire 编号 理由  作废某条它自写的原则（编号见 :principles；理由必填）
                  作废后不会复活：反思是确定性的，重跑也不会把作废的原则再写回来
    :backup       给记忆库拍一份快照到 data/backups/memory-时间戳.db（已存在不覆盖）
    --- 情感与自我（Phase5.6：DeepSeek 交付，守门人并入）---
    :mood         看当前的【心境估计】（基调/强度/线索 + 上次更新时间）
                  ※是系统内部的功能态估计，不是诊断，也不代表它真的有感受（铁律3）
    :self         看它的身份记录：它在守什么边界、版本几号、改过几次口
    :revisions    看它自写原则的【改口流水】：旧话→新话 + 当时写的理由
    :log          看最近对话
    :exit         退出
    python chat.py --reset   清空记忆、从头开始

怎么接真实模型（opt-in，密钥绝不进对话/文件/库）
------------------------------------------------
默认永远走 mock；只有你显式设了 provider 才打真实 API。

★最省事的一条：双击  接MiniMax-粘Key就行.bat
    它只做三件事：让你把 Key 粘进【看得见】的一行 → 跑一次本地自检（不联网、不扣费）
    → 问你要界面还是命令行（输入 q 就停在自检，什么都不启动）。
    密钥只进这个窗口的环境变量，关掉窗口就没了：不写文件、不进记忆库、不进 D:\Q。
    为什么特意做成"看得见"：--live 用的是 getpass 盲输，粘漏一个字符也看不出来，
    连着几轮"我已经输了但报错"就卡在这。现在当场报字符数，粘没粘上一眼能判。
    代码在 tools/minimax_quickstart.py（它只调用同一份自检，没有第二套规则）。

★先说一件容易绕晕的事（Boss 2026-10-21 也绕进去过一次）：变量名里的 OPENAI 指的是
【协议】（OpenAI 兼容的 /chat/completions），不是 OpenAI 这家公司。接 MiniMax 就是
provider=openai + 把 base_url 指到 api.minimaxi.com + 填 MiniMax 的 Key ——
名字不对上但路是对的。已定【不给网关加 minimax 别名】：动它要改 ADR-017 冻结的契约，
收益只是好看，不值（见黑板 ADR-041）。

                                                            :: 这是本机实际路径，换机器改这一行
    set PAI_MODEL_PROVIDER=openai
    set PAI_OPENAI_BASE_URL=https://api.minimaxi.com/v1

   MiniMax-M3.1-Flash（便宜四倍：输入 1.0 对 2.1，输出 4.0 对 8.4）。

以 MiniMax（OpenAI 兼容协议，base_url=https://api.minimaxi.com/v1，无需 GroupId）为例：

    set PAI_MODEL_PROVIDER=openai

PowerShell 写法：$env:PAI_MODEL_PROVIDER="openai"; $env:PAI_OPENAI_BASE_URL="https://api.minimaxi.com/v1"; $env:PAI_MODEL_NAME="MiniMax-M3.1-Flash"。

★为什么 bat 里一个中文都不能有（v0.38 踩出来的，有测试钉着）：
    cmd 是按【字节】切行的，GBK 汉字占两字节、第二字节常正好落在竖线或反斜杠的位置，
    于是整行被拆断 —— 报的却是 "'xxx' is not recognized as an internal or external
    command"，看着像路径错，其实是中文。我把中文提示写进 bat 试过两版，两版都断在这儿
    （第一版还多了 chcp 65001，断得更狠）。正确形状：bat 只留 ASCII 四行，
    所有中文由 Python 说 —— Python 按控制台编码往外写，GBK 窗口显示中文毫无问题。
    同一类坑还有屏显字符：一个对勾 emoji（U+2705）就能让 check_key.py 在 GBK 窗口里
    当场 UnicodeEncodeError，整份报告一个字都看不到，Boss 只见到窗口一闪。
    tests/test_console_encoding.py 钉住三条：扫全部脊柱 .py 与 *.bat 的字符/字节，
    再真的用 gbk 编码起一个子进程跑一遍自检，要求它跑到最后一行「结论」。
    ★所以以后往脊柱里加话，别用 GBK 编不出的字符，也别往 bat 里写中文。

【重要防呆】密钥只在 `OPENAI_API_KEY >` 这一步盲输；不要把 Key 打进 `你 >` 当聊天内容
   —— 那样它会变成"你说的话"被存进记忆库。内核已加护栏(orchestrator._looks_secret)：
   疑似 sk-/Bearer/私钥 的输入会被【拦截、不落库、不联网、不复述】并提示你改到正确位置。
   若 MiniMax 返回 401/1004，多半是 Key 本身无效/过期/撤销，或【按量付费Key】与
   【订阅(Token Plan)Key】用混了(两者端点不同)——不是本系统代码问题。可先自验：
   curl https://api.minimaxi.com/v1/models -H "Authorization: Bearer <你的Key>"
   能列出模型＝Key 有效；仍 1004＝换一把对应端点的、有余额的 Key。
