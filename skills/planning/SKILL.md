# 规划循环（planning）

## 何时使用
- 用户给了一个需要多步完成的办公目标，例如"帮我写一份周报，保存成文件""整理这周的会议纪要"。
- 用户说"拆成步骤""一步步做""先给个计划"。
- 不用于一句话就能答完的问题（那种走对话技能）。

## 怎么做
1. 调 `POST /api/plan`，传 `{"goal": "目标"}`，得到 `plan_id` 和拆好的步骤（`create_plan()` 会调模型拆成 3-6 步，存进 `plans` / `plan_steps` 表）。
2. 一步步执行：调 `POST /api/plan/step`，传 `{"plan_id": id}`，每次只走一步（`run_plan_step()`）。执行完一步再点下一步，不要一次全跑完。
3. 如果某步产出文件，模型会用 `[写文件: 文件名]` 的格式输出，文件先进入待审批（`pending_files` 表），等用户批准才写进 `workspace/`。
4. 全部步骤做完后，调 `POST /api/plan/reflect` 做一次自我检查。
5. 规划和自我检查比较吃模型，API 模式（免费 70B）比本地小模型效果好；如果用户用本地模式，提醒他效果可能有限。

## 验收标准
- 计划拆成 3-6 步，每步一句话、可执行，不含糊。
- 每步执行完都有结果记录（`plan_steps.result` 非空），步骤状态从 pending 变 done。
- 写文件必须先进待审批，不能直接落盘。
- 计划和步骤存在本地数据库（`local_office_memory.db`），重启也不丢。
