# 低配版 Muse v2.2

## v2.2 新增（四个能力，都是加法，v2/v2.1 的东西没动）

1. **记忆语义搜索**。记忆除了关键词搜，还能按意思搜：记忆页搜框旁边多了"关键词 / 语义 / 混合"三种模式。做法学 sqlite-vec（向量存 BLOB，余弦算相似度）；装了 `sqlite-vec` 就用它的 vec0 虚拟表加速，没装就用 Python 算；嵌入用 Ollama 的 BGE-M3。**都是可选的**：没装 BGE-M3 时自动退回关键词搜索，App 不会崩。
2. **技能包**。`skills/` 目录里有 6 份 SKILL.md（规划、文件审批、自我检查、对话、定时任务、文档处理），格式学 anthropics/skills（触发条件 + 操作手册 + 验收标准），内容是我们自己的。任务匹配到技能时自动引用它的步骤；设置页里能看到全部技能，点开看全文。
3. **文档导入**。把 PDF/Word/Excel/txt/csv/html 放进 App 目录下的 `inbox/` 文件夹，在任务页点"导入"转成 Markdown；转完先到"待审批"，你批准了才写进 `workspace/`，和模型写文件走同一条审批。转换优先用 `markitdown`（装了 `markitdown[docx,xlsx,pdf]` 才能读 docx/xlsx/pdf），没装时内置转换器只读 txt/md/csv/json/html。
4. **标准对话接口**（2026-11-26 新增）。`POST /v1/chat/completions`，OpenAI 兼容，本机回环（只绑 `127.0.0.1:8080`，不出本机）。接口做法学 PolyStrata（只学接口，不抄引擎/代码）：标准客户端（OpenAI SDK、Claude Code 这类工具）把 base URL 指到 `http://127.0.0.1:8080` 就能直接驱动它，不用再手动复制 Issue 文字。请求走现有的对话流程（记忆、技能、规划格式、文件审批全都不变），回复是标准 `chat.completion` 形状，另附一个 `lowspec` 字段（来源/技能/存下的脚本）。请求里的 `model` 字段只作参考，实际用的永远是本机配置好的模型；`stream` 暂不支持（会明确返回 400）；`load`/`unload` 没做——本地没有要加载/卸载的重型模型，Ollama 自己管模型。另有 `GET /v1/models`（已配置的模型列表）和 `GET /v1/status`（运行状态）。

跑在你自己电脑上的个人 AI 助手。目标：**人人都能免费 AI 办公**。

- 硬件门槛低：2 核 CPU、8GB 内存、无显卡就能跑。

## v2 新增（v1 的对话、记忆、定时任务、代码、设置全都在）

1. **任务页：规划循环**。给一个目标（例如“帮我写一份周报，保存成文件”），模型先拆成 3-6 步，展示计划，一步步执行，每步结果都记下来。点“执行下一步”走一步，做完一步再点下一步。
2. **文件审批**。模型想写文件时，不直接写，先放进“待审批”。你点了“批准”才真正写进 `workspace/` 文件夹；点了“拒绝”就不写。只允许 `workspace/` 下的直接文件，后缀限 txt/md/csv/json/html/py，单个文件不超过 1MB，路径穿越和可执行文件都被挡住。
3. **自我检查**。任务做完后，点“自我检查”，模型自己审一遍结果，只审一次，给出“通过”或要改的地方。

**不做的**：MCP（太重）、记忆分层（现有记忆够用）。保持轻、免费、老电脑能跑。

**提醒**：规划和自我检查比较吃模型，本地小模型（3B、4B）效果有限，API 模式（免费 70B）更合适。

## 怎么跑

1. 装 Python 3.10+（勾选 Add to PATH），装 Ollama（https://ollama.com）。
2. 拉两个本地小模型（断网备选才用得到）：
   - `ollama pull qwen3:4b`
   - `ollama pull qwen2.5-coder:3b`
   - 可选（只想用语义搜索才拉）：`ollama pull bge-m3`（嵌入模型，给记忆算向量；不拉也能用关键词搜索）
3. 双击 `start.bat`，浏览器打开 http://127.0.0.1:8080。
4. 去「设置」里选模型：
   - 想用大模型：选 Groq 或 OpenRouter :free，填免费 key（获取地址在设置页里，不花钱、不绑卡）。
   - 不想填 key：什么都不用做，默认自动模式会直接用本地小模型。
   - 断网时自动走本地，不用你操心。

## 免费 API key 去哪拿（都不花钱）

- Groq：https://console.groq.com/keys（注册后建一个 key）
- OpenRouter :free：https://openrouter.ai/keys（注册后建一个 key，模型名带 `:free` 的都是免费）

key 只存在你电脑上的 `muse_config.json`，不上传、不发给别人。

## 有什么功能

- 对话：聊天、写代码、写脚本、做分析；回答里的代码自动存到「代码」页，只存不执行。
- 任务：给目标，拆步骤，一步步执行；写文件先审批；做完能自我检查一次。
- 记忆：你说过的话、AI 的回答都记进本地数据库，可搜索。记忆页能选"关键词 / 语义 / 混合"三种搜法；语义搜索要先拉 `bge-m3`，没拉时自动退回关键词。
- 定时任务：设个时间（例如每天 21:30 写日报），到点自动跑，结果记进记忆。
- 设置：模型模式、服务商、key、模型名都能改，保存后立即生效；设置页里能看到 6 个技能包（SKILL.md）。
- 文档导入：把 PDF/Word/Excel/txt/csv/html 放进 `inbox/`，在任务页点"导入"转成 Markdown，先审批再进 `workspace/`。
- 标准对话接口：`POST /v1/chat/completions`（OpenAI 兼容，本机 `127.0.0.1:8080`），标准客户端直接连，不用手动复制任务文字；另有 `GET /v1/models`、`GET /v1/status`。

## 标准对话接口怎么用

服务跑起来后（`start.bat`），接口在 `http://127.0.0.1:8080`，只接受本机请求。

```bash
curl http://127.0.0.1:8080/v1/chat/completions -H "Content-Type: application/json" -d "{\"model\": \"qwen3:4b\", \"messages\": [{\"role\": \"user\", \"content\": \"帮我看看 GitHub Issue #1 怎么修\"}]}"
```

- 回复是标准 `chat.completion`：`choices[0].message.content` 是回答，`model` 是实际用的模型，`usage` 是粗略 token 估算，`lowspec` 里有来源、技能和存下的脚本。
- `messages` 里有多条 user 消息时，取最后一条作任务；`stream: true` 会返回 400（暂不支持流式）。
- 发任务给它（例如把一段 GitHub Issue 全文当 user 消息发过去），它会像在网页对话里一样处理：记进记忆、匹配技能、回答里的代码存进 `scripts/`，想写进 `workspace/` 的文件先到"待审批"，你批准了才写。
- OpenAI 兼容的客户端（Python `openai` 包、Claude Code 等）把 base URL 设成 `http://127.0.0.1:8080`、model 填本机配置好的模型名就能用。

## 第一次运行要验证什么

1. 打开页面，顶栏显示「运行中 · auto模式」。
2. 不填 key 直接发一句话：如果 Ollama 在跑，能收到本地模型的回答，来源显示「本地」。
3. 填了免费 key 后再发一句话：来源显示「API」，回答明显更强。
4. 拔网线（或关掉网络）再发一句话：自动切回本地，来源显示「本地（API 失败后自动切换）」。
5. 去「任务」页写个目标（例如“写一份周报，保存成文件”），点“生成计划”，看它拆成几步；点“执行下一步”，走完后看“待审批”里有没有文件，批准后去 `workspace/` 文件夹确认文件在。
6. 任务做完点“自我检查”，看它能不能审出问题。
7. 加一个定时任务，确认它出现在列表里；第二天到点看它是否执行并记进记忆。
8. （v2.1 新增）中文输入法检查：打开拼音输入法，输入“你好”组字中按 Enter，必须**不**发送；组字结束后再按 Enter，正常发送。搜索框和任务目标框同样试一次。
9. （v2.2 新增）语义搜索：先 `ollama pull bge-m3`，然后去记忆页搜一个意思相近但关键词不同的词（例如记忆里有"写日报"，搜"周报"），选"语义"模式，看它能不能找出来；再把模式切回"关键词"，确认原来的关键词搜索还在。
10. （v2.2 新增）技能包：去设置页看技能列表，点开"规划循环"看 SKILL.md；再去对话页发一句"帮我写一份周报"，看回答下面有没有"技能：规划循环"。
11. （v2.2 新增）文档导入：往 `inbox/` 里放一个 txt 或 Word 文档，去任务页点"刷新收件箱"，点"导入"，看它是不是出现在"待审批"里；批准后去 `workspace/` 确认 `.md` 文件在；没批准之前 `workspace/` 里不应该有它。
12. （2026-11-26 新增）标准对话接口：先在浏览器打开 http://127.0.0.1:8080/v1/models，应看到已配置的模型列表；再用上面"标准对话接口怎么用"里的 curl 发一次，应收到标准 `chat.completion` 回复，且对话页记忆里多了一条你发的内容。

## 注意

- 这是 v2.2，聊天和任务本身还没在你电脑上真跑过 Ollama / 真调过 API（本机实测用桩模块验证了 v2 的 10 项和 v2.2 的 65 项（本机无可选依赖环境 65 项全过；有 markitdown/sqlite-vec 的环境应为 69 项，待补跑）：建计划、执行步骤、文件审批、自我检查、语义搜索、技能包、文档导入、HTTP 接口、标准对话接口全通过；另用真实 Issue #1 全文走了一次标准接口，10/10 通过）。第一次在你电脑上跑，以上面 12 条为准。
- 模型名默认：Groq 用 `llama-3.3-70b-versatile`，OpenRouter 用 `meta-llama/llama-3.3-70b-instruct:free`。如果某天免费模型改名了，在设置里把模型名改掉就行。
- 定时任务用的是你电脑本地时间；电脑关机时任务不会跑，开机后恢复。
- 任务执行和自我检查每次都要调一次模型，会消耗免费额度。Groq 免费层每天 1000 次请求，一般个人用够了；OpenRouter :free 每天 50 次（不绑卡），省着点用。

> 边界：守卫逻辑是用真实输入法事件序列模拟测的（compositionstart → keydown 229 → compositionend），没在真浏览器里接真拼音输入法测过。落到你电脑上，发中文消息前先按上面第 8 条试一次。
